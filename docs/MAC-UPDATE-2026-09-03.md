## التثبيت والفحص

استخدم Node22.13+ ضمن22.x أو24+. المستخدم وثّق نجاح22.23.2 سابقاً؛ اختبارات هذه الجولة جرت على24.19.0.

```bash
npm ci
npm run preflight
npm run typecheck
npm run lint
npm test
npm run build
npm run start -- --hostname 127.0.0.1 --port 3002
```

افتح `http://localhost:3002/ar`، وكذلك `/ku` و`/de` و`/en`. للتطوير بدلاً من start:

```bash
npm run dev -- --hostname 127.0.0.1 --port 3002
```

احتفظ بإعدادات Supabase الحالية. يجب أن يكون مصدر البيانات `supabase` ورابط الموقع الإنتاجي `https://rojdeal.app`. لا تنقل إعداد mock من تقارير الاختبار إلى إعداداتك. ملفات البناء وnode_modules والإعدادات السرية غير موجودة في ZIP.

## اختبار الأولوية

1. مستخدم غير مسجل يضغط إضافة إعلان: تسجيل الدخول ثم الرجوع إلى النموذج في اللغة نفسها. مستخدم مسجل يفتح النموذج مباشرة.
2. جهّز إعلان اختبار مصرحاً به. جرّب خطأ حقل ثم تصحيحه، وانقطاعاً أثناء رفع صورة ثم إعادة المحاولة. يجب أن تبقى المدخلات والملفات وألا يتكرر الإعلان أو الملف الذي اكتمل رفعه.
3. فشل نشر بعد حفظ المسودة: صحح السبب وأعد النشر **من النموذج نفسه**. الجلسة لا تُلغى بسبب خطأ شبكة/صلاحية. إذا انتهت فعلاً، رابط تسجيل الدخول يفتح تبويباً آخر لحفظ النموذج الحالي؛ ارجع إلى الحساب نفسه.
4. تعديل الاسم والصورة؛ افتح حسابك في التطبيق وتأكد من ظهور البيانات. جرّب إعلاناتي/الإحصاءات/ملف المعلن/الإبلاغ فقط ببيانات اختبار مأذون بها.
5. سجّل الخروج من الموقع وتأكد أن التطبيق ما زال مسجلاً. استعادة كلمة المرور تخضع لسياسات Auth الأصلية ولم نغيّرها.
6. اختبر الحساب العادي والدعم والمشرف المحدود والأدوار الإدارية المصرح بها. يجب أن يرفض Backend طلباً غير مصرح به مباشرة عبر API، لا إخفاء الزر فقط.
7. أحجام مقترحة لمحاكاة المتصفح:390×844،768×1024،1440×900، ثم جهاز حقيقي. راجع `DEVICE-ACCEPTANCE.md` وسجّل النتيجة الفعلية.

Google OAuth يحتاج عنوان الرجوع المحلي ضمن قائمة Supabase المسموح بها. لم نغيّر تلك القائمة. إذا عاد Google إلى الإنتاج بدلlocalhost، هذه ليست شهادة نجاح للنسخة المحلية؛ يلزم اعتماد عنوان اختبار مناسب من صاحب المشروع. لا ترسل مفاتيح سرية أو كلمات مرور في المحادثة.

## النشر

لم نعد النشر. الموقع الموجود بالفعل هو `rojdeal.app` عبر Cloudflare Workers/OpenNext. بعد مراجعة التغييرات واجتياز الاختبار الحقيقي، أمر النشر الموجود يبقى:

```bash
npm run cf:deploy
```

هذا إجراء منفصل يتطلب موافقتك، وليس جزءاً من أوامر التثبيت والفحص أعلاه. لا تشغّل `supabase db push`؛ هجرة الدعم المقترحة في المصدر لم تُنفّذ وتحتاج مراجعة مستقلة وأثرها على التطبيق.
