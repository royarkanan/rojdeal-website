# RojDeal — ملف العمل الموحّد قبل النشر

تاريخ الفحص: 2026-09-01. هذه النسخة تجمع التعديلات في مشروع واحد؛ ليست موافقة نهائية على النشر. لا تُطبّق ملفات SQL على الإنتاج قبل مراجعة المخطط الحالي. لم يُغيّر موقعك على الماك أو الدومين أو بيانات Supabase.

## نتائج مؤكدة محلياً

- TypeScript: نجح.
- ESLint: لا أخطاء ولا تحذيرات تخص الكود؛ أمر next lint نفسه يعرض تنبيه تقادم.
- اختبارات الدوال والخدمات المعزولة: 17/17 ناجحة. تشمل استدعاء خدمة الدعم وترقيم صفحات الإدارة بقواعد بيانات بديلة للاختبار؛ ليست اختبارات قاعدة البيانات الحقيقية.
- بناء Next.js: نجح ببيانات mock، دون اتصال بقاعدة بيانات الإنتاج.
- فحص HTTP: 40 مساراً وحالة رابط عبر اللغات الأربع أعادت 200، بما فيها معاملات بحث مكررة وأسعار غير صالحة. ليس اختباراً بصرياً أو اختبار حسابات.
- npm audit --omit=dev: صفر ثغرات معروفة وقت الفحص. لا يثبت ذلك أمان التطبيق أو صلاحياته.
- لم تُضف مكتبات أو تُرقَّ إصدارات الاعتماديات في هذه الجولة.

## التغييرات الموجودة في نفس المشروع

آخر إضافات المشروع الموحّد: إشعار مباشر للمستخدم من قسم المستخدمين باستعمال queue_admin_direct_message وبصلاحياته الموجودة، وترقيم صفحات الإدارة للإعلانات والدعم والترقيات (50 عنصراً في الصفحة)، والبحث في طلبات الدعم بالعنوان والبريد وUUID. أضيف التحقق من معاملات البحث المكررة والفئات غير المعروفة والأسعار غير الصالحة وتوحيد نطاق السعر المقلوب، مع تحديث اختيار المدن عند تغير الرابط. ترقيم صفحات قوائم الزائر وسجل الدعم الشخصي ما زال متبقياً.

## ما يمنع إغلاق المهمة نهائياً

تحديث بعد استلام schema_review وملف السياسات: تمت مراجعة 663 عموداً وتعريفات الدوال الثمانية. تأكد أن سياسة الدعم تعتمد is_admin بينما صلاحية الواجهة تعتمد can_staff('support'). أضيفت دالة مقترحة web_update_support_request بصلاحيات محددة والتحقق من الحالة والملاحظة وسجل القرار وإشعار العميل، دون توسيع UPDATE العام. كما أضيف تحذير وتأكيد صريح بأن تعيين الموظف الحالي يستبدل كل تعييناته دون نطاق جغرافي. هذه التغييرات محلية ولم تطبق على قاعدة البيانات. لم تعد الحاجة لتصدير الأعمدة والدوال المذكورة عائقاً؛ يبقى اختبار التنفيذ والحسابات والمنح والتريغرات الحقيقية مطلوباً.

1. تم استلام ملفات الأعمدة والدوال والسياسات ومراجعتها. لا يتوفر اتصال بقاعدة البيانات لتنفيذ اختبارات التكامل؛ لا تعِد تصدير الملفات نفسها. ملف supabase/READONLY-SCHEMA-CHECK.sql يبقى أداة قراءة فقط عند الحاجة مستقبلاً.
2. الهجرة supabase/migrations/20260901140000_web_support_threads.sql مقترحة وغير مطبقة. تعتمد على جداول ودوال التطبيق التاريخية. يلزم اختبارها في بيئة اختبار، ثم اختبار مستخدم عادي وموظف وصاحب المنصة.
3. Google OAuth واستعادة كلمة المرور وSMTP تحتاج إعدادات الحساب واختبار وصول الرسائل فعلياً. تحويل support@rojdeal.app إلى Outlook لا يفعّل إرسال رسائل استعادة كلمة المرور.
4. المطابقة المرئية الكاملة على iPhone وAndroid وiPad والكمبيوتر، حذف الحساب، المحادثات ورفع الوسائط لم تُختبر طرفاً إلى طرف.
5. بقيت تحسينات برمجية غير مكتملة: ترقيم صفحات قوائم الزائر وسجل الدعم الشخصي، ضبط جميع نطاقات الموظفين في واجهة التعيين، تاريخ نسخ المحتوى وتعارض التحرير، وتحسين SEO الخاص بالصفحات. ترقيم صفحات الإدارة للإعلانات والدعم والترقيات تم تنفيذه، ولم يُختبر ببيانات الإنتاج بعد.
6. التهيئة النهائية للاستضافة على Cloudflare غير مضافة أو مختبرة بعد. هذا مشروع ذو مسارات ديناميكية؛ لا يُعامل كملفات HTML فقط. راجع مسارات النشر الرسمية قبل تثبيت أداة ترحيل:
   - https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/
   - https://opennext.js.org/cloudflare/get-started
   لا تشغّل أوامر نشر أو ترحيل تلقائي قبل اختيار المسار واختباره. لا توجد تغييرات DNS هنا.

## أوامر الفحص داخل مجلد المشروع

```sh
npm ci
npm run typecheck
npm run lint
npm run test
npm run build
npm audit --omit=dev
npm run preflight
```

preflight يقرأ الإعدادات المحلية دون طباعة المفاتيح، ويتوقع بيانات Supabase الحقيقية وNEXT_PUBLIC_SITE_URL=https://rojdeal.app. نجاحه لا يتحقق من الخادم أو وصول البريد.

للفحص التجريبي فقط: NEXT_PUBLIC_DATA_SOURCE=mock npm run build ثم npm run test:smoke.
لا تنشر بناء mock. لا تُرسل ملف .env.local أو أي مفاتيح سرية.

## سياسة النسخ

نستخدم هذا المشروع نفسه للتجميع. لا حاجة لتثبيت ترقيعات متفرقة أو حذف النسخ القديمة الآن. احتفظ بنسخة الماك الحالية إلى أن يجتاز المرشح الموحد اختبارات التكامل. صناديق بريد الموظفين والإعلانات المدفوعة مؤجلة، وليست ضمن خدمة تحويل البريد الحالية.

## إضافات المستخدم — أولوية قبل النشر (2026-09-01)

الحالة لجميع البنود التالية: **مفتوحة، غير منفذة أو غير مثبتة بالاختبار الفعلي**. هذه الإضافة لا تحذف ولا تستبدل أي مهمة سابقة. ترقيم صفحات الإدارة المنفذ سابقًا لا يُغلق مهمة ترقيم قوائم الإعلانات العامة.

- [ ] الاحتفاظ بكلمة البحث والقسم والموقع والفلاتر وترتيب النتائج عند الانتقال بين الصفحات.
- [ ] اختبار الترقيم على Desktop وTablet وMobile.
- [ ] عدم قص النتائج أو منع التمرير إلى نهاية الصفحة باستخدام overflow: hidden أو ارتفاع ثابت غير مناسب.

### WEB-P02 — الوصول إلى Footer والروابط القانونية

- [ ] يظهر Footer كاملًا بعد آخر إعلان وأزرار Pagination، ويمكن الوصول إليه مهما زاد مجموع الإعلانات.
- [ ] لا يحجب شريط التنقل السفلي روابط Footer على الهاتف.
- [ ] تضمين النص الألماني التالي وروابطه الصحيحة، والمقابل الملائم في اللغات الأخرى:

- [ ] اختبار النقر على كل رابط والتأكد من الصفحة واللغة والفئة المقصودة؛ وجود الرابط وحده لا يعني أن الصفحة مكتملة.

### WEB-P03 — حذف حساب Staff/Admin ومراجعة Owner

دليل المستخدم: ظهرت الرسالة `staff_account_requires_owner_review` أثناء طلب حذف الحساب. يشير الرمز إلى مراجعة حساب الموظف من المالك؛ يجب التحقق من المسار الخلفي الفعلي. عبارة سبب الحذف مثل «Ich möchte meinen Account löschen.» ليست سبب الخطأ المذكور.

- [ ] اختبار مسار طلب/تنفيذ حذف الحساب العادي، والبيانات المرتبطة، والنتيجة التي يراها المستخدم.
- [ ] منع حذف حساب إداري بطريقة تضر بإدارة المنصة، وعدم تجاوز الصلاحيات أو إزالة الحماية لمجرد إخفاء الخطأ.
- [ ] توفير مسار واضح ومحمي للمالك لمراجعة طلب الموظف، اتخاذ القرار، وتنفيذ الحذف الآمن مع إشعار النتيجة؛ عرض رسالة مفهومة وحده لا يُكمل المسار.
- [ ] عدم عرض الرمز التقني للمستخدم، وترجمة الرسالة باللغات الأربع:
  - العربية: «هذا حساب إداري/موظف، لذلك يجب مراجعة طلب الحذف من قبل المسؤول الرئيسي.»
  - Deutsch: «Dieses Mitarbeiterkonto kann nicht automatisch gelöscht werden. Die Löschung muss vom Hauptadministrator geprüft werden.»
  - English: «This staff/admin account cannot be deleted automatically. The platform owner must review the deletion request.»
  - Kurmancî (مسودة للتدقيق): «Ev hesabê karmend an rêveber e û nikare bixweber were jêbirin. Divê xwediyê platformê daxwaza jêbirinê binirxîne.»
- [ ] اختبار مستخدم عادي وموظف/مشرف ومالك في بيئة اختبار، مع التأكد من أن غير المالك لا يستطيع تجاوز المراجعة وأن حماية إدارة المنصة باقية.

### WEB-P04 — شرط إغلاق البنود

ترتيب الأولوية: WEB-P01 ثم WEB-P02 ثم WEB-P03، ويتبعها التحقق الشامل. لا توضع علامة «مكتمل» قبل تسجيل الجهاز والمتصفح والسيناريو والنتيجة الفعلية، مع اختبار Desktop وMobile على الأقل وTablet للتصميم. نجاح TypeScript أو البناء أو اختبارات الدوال لا يحل محل هذا الاختبار.

لم تتغير ملفات التطبيق أو قاعدة البيانات أو ملفات جهاز المستخدم بسبب إضافة هذه الملاحظات؛ التغيير في قائمة المهام فقط.
